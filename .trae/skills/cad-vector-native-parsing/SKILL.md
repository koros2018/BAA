# CAD 矢量原生解析约束

BAA 项目的图纸解析铁律，源自 YOLO 路线证伪（mAP50=0.001）与 32% 图元未分类两次重大教训。

## 红线

1. **禁止以渲染光栅图像作为解析主干**。CAD 语义（图层名、块名、XData、文字标注）只存在于矢量数据中，渲染后不可逆丢失。DXF LINE 零厚度渲染 <1px，视觉模型无法学习。YOLO/分割模型仅可作为消防设备符号的专项补充，且须先完成矢量块名/图例查表基线验证。
2. **禁止块展平时丢弃块名与属性**。块展平丢失语义是真实图纸 32% 图元无法分类的根因。块引用提取必须保留：块名、插入点、旋转、缩放（ezdxf 字段名为 `xscale/yscale`，非 `x_scale`）、图层、属性。参考 `src/baa_engine/parsers/block_refs.py`。
3. **禁止对传入 analyze() 的图元调用 to_dict()**。审查链路只传原始图元对象（带 `.layer`/`.bbox` 属性），to_dict 仅用于前端/缓存出口。

## 房间识别（扫线法）要点

- 扫线法（左手定则平面面遍历）是房间/走廊/门洞识别的主干，精度为确定性而非概率。
- 扫线法上游必须排除三类区域：titleblock 图层、表格网格区域、图框边框。
- 图框排除只排除**贴在边框上的图元**，禁止排除整个 bbox 内图元（会造成灾难性误排）。
- 表格识别用几何网格多维度判据（单元格数量 + 单元格尺寸 + 图层），单一通用判据在真实图纸上会失效。
- 走廊判据：宽高比 ≥3.0 且短边 ∈ [2000, 4000]mm。

## 天正 T3 解析

- 必须覆盖三类存储形态：T3 加密、T0 明文、自定义对象 XData。不得只做几何转换。
- XData 探测需尝试多 AppID；门窗识别需查块名。
- 加密 T3 解析出 0 图元时必须输出 parse_status 诊断，不得静默返回空。

## DWG 解析

- 依赖 ezdwg（已在 requirements.txt），缺失时优雅降级并明确提示。
- 解析管线为六级兜底：aspose-cad → ezdwg export_dxf → LibreCAD → manual → raw decode。

## 验收要求

- 任何解析改动必须跑真实图纸基线：`pytest -m real_drawing src/tests/test_real_drawings.py -q`（预期 8 passed）。
- 基线数值变更必须附证据链（图纸 ID + 根因分析 + 前后对比），禁止无依据调整。
- 统计汇总必须同时报告误报率与漏报率，单一指标无效。
