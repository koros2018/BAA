## 1. 背景与根因

`classify_sheet_type` 只能给出**整张图纸**一个 `scope_mode`。当混合图集（平面图区 +
立面/剖面/大样区共处同一 DXF）整体被判为 `plan` 时，非平面子区里扫线派生的假房间/
假走廊会照常进入逐实体判定，产出一堆无意义 findings。

Stadion 案例：整图被判 `plan`（有平面证据），但 y∈[54.9k, 75.9k] 与 y∈[86.3k, 99.6k]
两个 section 带内，看台踏步/排次格间被扫线法切出 44 个标准矩形面，全部进入审查。

## 2. 设计

### 2.1 子视框聚类（`classify_view_frames`）

新增于 [drawing_classifier.py](file:///d:/OpenClawData/BAA/src/baa_engine/drawing_classifier.py)：

1. 收集所有有合法 bbox 的原始图元质心 (cx, cy)；
2. 按 cy 升序做「gap 聚类」：相邻差值 > `_VIEW_GAP_MM=5000mm` 则切段，每段代表一个子视框；
3. 对每段统计内容证据并打分：
   - **正面**：闭合多边形数 ≥8 且面积 ≥2㎡（+2/个，封顶 30）、房间文字（+3/个）、
     尺寸标注 ≥5（+2/个）、门/出口文字（+3/个）、楼梯文字（+1/个）；
   - **负面**：立面/剖面文字（−10/个）、超长横线占比 >20%（−3/个，封顶 30）、
     图元密度 <3/m（−10）；
4. 得分 < `_VIEW_NON_PLAN_SCORE=20` → `non_plan`；20–30 → `unknown`；≥30 → `plan`。

### 2.2 单位归一化时序

**关键**：聚类阈值按毫米设计（5000mm），必须在**单位归一化之后**调用。
若在归一化前调用（源单位为米时坐标在 0-100 量级），会因尺度错位把所有图元聚成一簇，
返回空。故 `classify_view_frames` 调用被移到 `_normalize_parsed_geometry` 之后。

### 2.3 实体级过滤（`fp_rate_audit.py`）

`run_review` 中，逐实体本地函数判定前增加视图级覆盖：

```python
_non_plan_bands = [
    (vf["y_min"], vf["y_max"])
    for vf in result.view_frames
    if vf["scope_mode"] == "non_plan"
]
def _in_non_plan_view(bb):
    cy = bb["y"] + bb["height"] / 2
    return any(lo <= cy <= hi for lo, hi in _non_plan_bands)

for e in entities:
    if _in_non_plan_view(e.get("bbox") or {}):
        continue  # 非平面子视框内的实体不参与本地函数判定
```

只影响**逐实体本地函数**的 evaluated 计数与 findings；`applicable` 分母与全局
EXIST 检查保持原口径（与既有全局 `non_plan` 处理一致）。

### 5.3 结论

P121-V 视图级过滤**只影响混合图集（Stadion）**，且效果是**收窄**（evaluated 下降、
findings 不变），不引入任何新 finding，不改变任何其它图纸行为。符合「非平面子区
不参与逐实体判定」的设计意图。
