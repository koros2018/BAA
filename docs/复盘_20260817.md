## 三、核心问题（按致命程度排序）

### 3.1 产品层面：没有工作流闭环 🚨🚨🚨

这是**最致命**的问题。

**行业标准流程：**
```
上传 → AI审查 → 工程师逐条审核(确认/误报/待核实) → 整改通知单 → 复查 → 归档
```

**BAA现状：**
```
上传 → 审查 → 看文本列表 → 结束
```

**缺失：**
- ❌ 违规逐条审核（确认/误报/待核实）
- ❌ 整改通知单生成
- ❌ 前后版本复查Diff
- ❌ 多角色协作（设计师/审图/监理）
- ❌ 审批流
- ❌ 合规报告（PDF仅基础版，无封面/签字/模板）

**影响：** 即使审查引擎准确，用户无法形成"发现→处理→闭环"的完整工作流，产品停留在"演示Demo"阶段。

### 3.2 前端工程质量：几乎不可维护 🚨🚨

| 问题 | 证据 |
|------|------|
| 全局变量泛滥 | `baa-admin.js` 104个`var`，10个JS文件互相暴露全局函数 |
| 字符串拼接HTML | `baa-review.js` 72处`innerHTML+=`，`baa-ext.js` 25处，零模板引擎 |
| XSS防护为零 | 多数JS文件0处`escHtml` |
| 内联`onclick`硬编码 | index.html中72个 |
| 无前端测试 | 0个 |
| 无构建工具 | 无Webpack/Vite/Rollup，纯CDN加载 |
| 无模块化 | 10个JS文件全局函数互相调用，依赖加载顺序 |
| 无响应式 | 桌面端为主 |

**1,573行的`baa-review.js`是前端最大炸弹。** 任何修改都极可能引入回归，且无测试兜底。

### 3.3 后端异常处理：静默吞异常 🚨

- `baa_api.py`：3处`pass`空吞（行75/618/629）
- `drawing_parser.py`：多处`except Exception`无log无traceback
- `collab_routes.py`：多处`pass`

**后果：** 用户看到"审查完成"但结果空白，完全不知道为什么失败。这是生产系统的致命伤。

### 3.4 大文件/结构图可用性仅30% 🚨

135张真实图纸批量审查结果：
- OK 41张（30%）
- SKIP_STRUCT 59张（44%）
- SKIP_BIG 25张（18%）
- TIMEOUT 4张
- 未处理7张

**用户上传50MB图纸直接跳过，体验极差。** 结构图占44%直接SKIP，意味着近半用户场景不可用。

### 3.5 YOLO模型训练失败 🔴

P111 v2全量18类训练：mAP50=0.001，伪标签路径终止。消防设备类（烟感/喷淋/灭火器/消防栓等8类）完全缺失。

**根因：** 伪标签质量差 + 人工标注量不足。
**影响：** 消防设备类原子函数全部无法执行，审查覆盖度打折扣。

### 5.2 节奏问题

## 六、对后续开发的指导

### 6.1 立即停止做的事

| 行为 | 原因 |
|------|------|
| 再扩展原子函数数量 | 422个已足够，缺的是真实数据验证和精度提升 |
| 在现有前端架构上加功能 | 任何新增功能都会继续恶化技术债 |
| 继续YOLO训练 | 伪标签路线已证伪，需换路径 |

### 6.2 最该做的三件事（按价值排序）

#### 第一优先：P112续完 + 违规审核工作流
P112目前做到"审查记录关联team/project + 前端401修复"，但核心工作流（逐条审核确认/误报/待核实）还没做。这是**从Demo变产品的关键一步**。

#### 第二优先：异常处理全量修复
把所有`pass`空吞和`except Exception`无log全部改为有log+友好错误提示。成本极低（<2天），但直接影响用户信任。

#### 第三优先：大文件解析能力
结构图SKIP 44% + 大图SKIP 18%，共62%图纸不可用。优先解决结构图解析（P95已证xref不可行，需换策略），再解决大图分页解析。

### 6.3 前端重构路线图

```
Phase 1（1-2周）：安全修复 + 测试框架
  - 所有innerHTML改为安全渲染（escHtml/模板化）
  - 引入Playwright做关键流程E2E测试
  - 消除所有alert()

Phase 2（2-3周）：模块化重构
  - 引入Vite构建 + TypeScript
  - 全局变量→模块import/export
  - 10个JS文件→组件化（违规列表/审查面板/图纸渲染等）

Phase 3（2周）：交互体验
  - 拖拽上传
  - 违规点击跳转图纸定位
  - 逐条审核(确认/误报/待核实)
  - 分页/排序/过滤
```

### 6.4 YOLO替代方案

伪标签路径已证伪。替代选项：
1. **纯规则引擎扩展**：消防设备类用LAYER_RULES + 几何特征规则（尺寸/位置/文字标签），不依赖视觉模型
2. **采购/借用预训练模型**：用开源的建筑图检测模型（如CAD模型微调）替代从零训练
3. **放弃YOLO**：如果消防设备类原子函数可以通过规则层覆盖，直接移除YOLO依赖，减少系统复杂度

## 八、总结

BAA的核心价值主张是"AI驱动的图纸合规审查"，审查引擎的扫线法/原子函数体系是这个价值的技术底座，这部分做得扎实。但**产品力和工程质量是两条腿——一条长一条短**：

- **产品力**卡在"审查→结束"，没有形成工作流闭环，用户无法从审查结果走到整改闭环
- **工程质量**卡在前端（全局变量+无测试+无模块化）和异常处理（静默吞异常），每次改代码都在赌不会炸

**后续开发的北极星：** 先修工作流闭环（P112续完），再修前端安全+测试，再修大文件能力。不要继续堆功能数量——堆的是技术债。
