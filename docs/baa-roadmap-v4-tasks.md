# BAA Roadmap v4 · 开发任务列表与验收标准

> **来源**：`docs/baa-product-assessment-20261016.md`（第三方独立评估 · Roadmap v4）
> **基线**：`v2.5.79-stable` / 分支 `semantic-analyzer-layer-sharding-JM65bP`
> **用途**：将 v4 的四阶段 Roadmap 拆解为可派发、可验收的开发任务（Task）。
> **编号规则**：`T-<阶段><序号>`，并回溯关联缺口 `G*` 与 Roadmap 项 `A*/B*/C*/D*`。
> **通用 DoD**（对所有 Task 生效）：
> 1. 每个 Task 必须**真实数据验证**，同时覆盖**误报率与漏报率**。
> 2. 每完成一组功能打 `-stable` 标签，回退路径清晰。
> 3. 依赖变更**三同步**：`requirements.txt` + CI 环境 + 跨平台验证清单。
> 4. 真实图纸基线变更**必须附证据链**（图纸 ID + 根因 + 前后对比）。
> 5. 核心文件**先拆后写**；禁止 >1000 行继续堆叠、禁止 `pass` 空吞与裸 `except:`。

## 阶段 A（0–1 月）· 止损 + 破冰

### T-A1 止损感知路线（关联 A1）
**开发任务**
- 从生产主干移除 YOLO/分割（视觉）依赖，主干改为纯矢量解析路径。
- 将“消防符号 spot”保留为独立研究模块，不接入生产调用链。
- 在配置层增加 `vision.enabled=false` 默认开关与启动校验。

**交付物**：主干依赖图 + 关闭视觉后的回归报告。
**验收标准**
- [ ] 生产主干无任何光栅/视觉依赖（`grep` 依赖清单与 import 链无 YOLO/分割库）。
- [ ] 关闭视觉后 2224+ 存量测试全部通过、无新增 FAIL。
- [ ] 研究模块与主干物理隔离，主干运行时不被加载。

### T-A2 块语义分类（关联 G7 / A2）
**开发任务**
- 建设“块名 → 构件类型”映射表，并接入块引用（block_refs，S1 已产数据）。
- 实现“图例（图例表）查表”基线，与现有 `LAYER_RULES` 联合判定。
- 落库块属性（属性块/属性定义）到图元标注结构。

**交付物**：`block_semantics` 映射模块 + 图例查表器 + 未分类率统计脚本。
**验收标准**
- [ ] 图元未分类率相较基线下降 ≥50%。
- [ ] 映射命中案例出具前后对比证据链（图纸 ID + 命中块名）。
- [ ] 联合 `LAYER_RULES` 后不引入新增误报（误报率不上升）。

### T-A3 天正 T3 识别验收（关联 G8 / A3）
**开发任务**
- 构建 ≥3 张天正 T3 标注集（AutoLISP/pywin32 自动化 + 手动兜底）。
- 跑通 P127 管线，产出基线结果与差距报告。
- 补齐天正对象（墙/门窗/柱）原生识别到分类输出。

**交付物**：标注集（≥3 张）+ T3 基线报告 + 差距清单。
**验收标准**
- [x] 墙体识别 F1 ≥ 0.80。（d1/d2/d3 native 覆盖式 F1=1.0，见 docs/t3_acceptance/）
- [x] 门窗识别 F1 ≥ 0.75。（native 门/窗/合并 F1 均为 1.0；baseline 门 0、合并 0.170）
- [x] 差距报告逐类列明失配原因与后续动作。（t3_gap_report.md，含两轮修复与真实图纸库扫描发现）

### T-A4 属性抽取补齐（关联 G9 / A4）
**开发任务**
- 建立 尺寸/TEXT → 图元属性（宽度/长度/数量等）的注入补全链路。
- 修复“尺寸/长度全 0”的系统性缺失（消融实验已定位）。

**交付物**：属性注入模块 + 属性完整度统计。
**验收标准**
- [ ] 关键属性缺失率 ≤ 10%。（**未达标但持续收窄**：252 张实测 20.78% → 18.32%（T-A4 注入链）→ 16.33%（阶段 B 分类治理 M1–M4：墙厚配对 + 景观/电气图层守卫 + 图例学习器，累计 -4.45pp）；剩余缺口主体为 `0` 默认层无图例可学的未识别块与无标注窗线，无判别信号不臆测，待图例词条扩充/T-B1 拓扑根治；证据链 docs/ta4_acceptance/m_series_classification.md）
- [x] 依赖属性的原子函数（DIM/AREA/COUNT 等）结果可复算且正确。（DIM-113 死函数修复，复算测试通过，attrs_missing=0）

### T-A5 真实用户试用（关联 G27 / A5）
**开发任务**
- 准备 3–5 个真实项目图纸包 + 黄金标准 v2（原 9 张扩充）。
- 跑通审查全链路，产出审计报告样本。

**交付物**：项目包 + 黄金标准 v2 + ≥3 份审计报告样本。
**验收标准**
- [ ] 产出 ≥3 份可交付审计报告。
- [ ] 黄金标准扩充 ≥100 条标注。

### T-A6 MVP 定位（关联 G26 / A6）
**开发任务**
- 输出 1 页定位说明 + 1 页定价方案，完成 ≥5 次客户访谈。

**交付物**：定位页 + 定价页 + 访谈纪要。
**验收标准**
- [ ] 明确本地版 / SaaS / 插件三选一。
- [ ] 访谈结论能支撑（或否决）该定位（A 阶段门控）。

> **阶段 A 出口条件**：A3 完成且 A4 有明确 MVP 定位；否则阶段 B/C 重排。

## 阶段 B（1–3 月）· 证据链 + 产品化

### T-B1 拓扑显式化（关联 G10 / B1）
**开发任务**
- 将 `_build_planar_graph` 升级为 NetworkX DiGraph。
- 新增 `/api/v1/topology` 接口输出图结构（节点/边/房间）。

**交付物**：拓扑构建器 + 拓扑 API。
**验收标准**
- [ ] 拓扑节点数与真实房间数偏差 ≤ 10%。（**未达标·不可判定**：无房间 GT；三种文字参考口径偏差互斥（-52%/-55% 朴素 vs +222%/+556% 锚定），坐实参考不可判定且暴露扫线检出区与命名区大面积错位；已修复 stair 楼梯段误入房间集真实缺陷（A23 rooms 882→303）；根治依赖 T-A5 黄金标准 v2 建房间 GT；本轮不凑数；证据链 docs/tb1_acceptance/README.md）
- [x] 接口返回结构可被判定层消费（含连通/邻接关系）。（POST /api/v1/topology 输出节点/边/邻接表/连通分量全 JSON 化，12 单测；nx.Graph 决策记录于模块 docstring）

### T-B2 聚合作用域（关联 B2，修正 EXIST 误报）
**开发任务**
- 实现按防火分区/楼层聚合的判定作用域。
- 将判定从“单图元”升级为“作用域内聚合”。

**交付物**：聚合作用域判定引擎。
**验收标准**
- [x] EXIST 类误报率下降 ≥ 80%。（**100%**：30 张抽样 465 次函数对比，旧盲判通道 execute_missing_batch「类型存在仍判缺」的 465 个 critical 误报全部修正——447 转为带区域信息的 low 提示、18 确认覆盖；过程修复目标实体铺格恒 pass 缺陷 + 主链路死代码；证据链 docs/tb2_acceptance/README.md）
- [x] 聚合不引入漏报（漏报率不上升）。（missing 全图真缺语义与旧等价仍 critical；pass 要求全作用域命中、partial 仍可见——构造上无「旧报新不报」路径；量化 leakage_check OK）

### T-B3 召回量化（关联 G12 / B3）
**开发任务**
- 将漏报率与误报率并列为一级指标纳入 CI/报表。
- 扩建黄金标准库以覆盖漏报场景。

**交付物**：recall 指标管线 + 扩展黄金标准。
**验收标准**
- [x] 漏报率可量化（有分母、可复现）。（src/tools/recall_metrics.py：黄金标准点数为分母，复用 t3_acceptance 匹配口径；3 张 T3 gold 基线 opening_micro recall=0.9796（48/49，唯一真实漏报为平面内门 1 个）；B3d 人工核对剔除门窗表行 6 点 + 图框外标注点 5 个，gold 修正轨迹留痕 provenance rev2/rev3）
- [x] 漏报率呈持续下降趋势并有历史记录。（docs/recall_metrics/history.jsonl 追加式历史（ts+sha+指标，3 条含修正轨迹）；CI recall_gate（test.yml，gate-recall 0.75 防回归）；「持续下降」待后续治理迭代按历史序列验证——当前数字为修正标注后真实基线）

### T-B4 报告产品化（关联 G3 / B4）
**开发任务**
- 补齐报告模板：封面 / 签字 / 项目信息 / 条款索引 / 结论页。
- 支持 PDF + HTML + Excel 三种导出。

**交付物**：报告模板 + 多格式导出。
**验收标准**
- [ ] 以审图机构视角审阅可用，无空白章节。
- [ ] 三格式内容一致、条款索引可跳转定位。

### T-B5 协作前端收尾（关联 G5 / B5）
**开发任务**
- 补齐认证入口 + 团队空间 + 评论/审批 UI。

**交付物**：协作前端模块。
**验收标准**
- [ ] 全流程 E2E ≥ 8 用例通过（认证→团队→评论→审批）。

### T-B6 工作流闭环（关联 G1 / G2 / B6）
**开发任务**
- 打通“审查 → 审核 → 整改 → 复查 → 归档”全流程。
- 实现违规 ↔ 图元双向定位（图面联动）。

**交付物**：闭环工作流 + 图元双向定位。
**验收标准**
- [ ] 闭环端到端可演示（一次完整流转）。

## 阶段 C（3–6 月）· 工程化 + 生态

### T-C1 数据层升级（关联 G14 / G17 / C1）
**开发任务**：抽象数据层 → PostgreSQL + Alembic 迁移脚本。
**验收标准**
- [ ] 生产多副本共享存储可用（缓存/协作/历史迁移完成）。
- [ ] 迁移可重复执行且幂等，回滚路径清晰。

### T-C2 并发与扩展（关联 G15 / G20 / C2）
**开发任务**：分布式限流 + 服务无状态化 + HPA 配置。
**验收标准**
- [ ] 水平扩容 2→N 生效（吞吐随副本数上升）。
- [ ] 限流在多副本下一致生效（非单进程内存态）。

### T-C3 可观测（关联 G23 / G24 / C3）
**开发任务**：接入 `/metrics`（Prometheus）+ 结构化日志 + 告警规则。
**验收标准**
- [ ] 关键链路均有指标与告警（解析/判定/API）。
- [ ] 日志结构化可检索，告警可触达。

### T-C4 安全合规隔离（关联 G18 / G19 / G22 / C4）
**开发任务**：AGPL/GPL 依赖独立进程/微服务；细粒度 RBAC；关闭匿名默认放行。
**验收标准**
- [ ] 法务可出具合规说明（许可隔离清晰）。
- [ ] RBAC 支持细粒度权限；`API_KEYS` 为空不再放行匿名。

### T-C5 云端部署流水线（关联 P115 / C5）
**开发任务**：CI/CD + 生产配置管理。
**验收标准**
- [ ] `docker compose up -d` 后生产就绪（一键起服务）。

### T-C6 知识库开放（关联 P117 / C6）
**开发任务**：原子函数/规范 schema 版本化 + SDK 示例。
**验收标准**
- [ ] 一键导出知识库包。
- [ ] SDK 10 分钟内跑通（含示例）。

### T-C7 OCR 解阻塞（关联 G11 / C7，条件触发）
**开发任务**：获真实扫描件后接入 PaddleOCR/tesseract chi_sim。
**验收标准**
- [ ] ≥200DPI 扫描件识别率 ≥ 85%。

### T-C8 IFC/STEP 输出（关联 C8，延后支线）
**开发任务**：IfcOpenShell 输出 IFC4 + CadQuery 输出 STEP（独立文件）。
**验收标准**
- [ ] 5 张平面图 Hausdorff 距离 ≤ 2mm。
