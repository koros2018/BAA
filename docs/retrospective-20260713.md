## 二、核心问题诊断

### 2.1 原子函数的设计缺陷

当前每个原子函数是独立的 if-else + 简单类型匹配，存在三个系统性缺陷：

**（1）值提取缺乏"属性缺失"意识**

合成图纸有完备属性（width/area/count 等），真实图纸大量缺失。提取逻辑默认给 0.0 / 1.0 而不是 None → 大量误报。今天修的 4 个函数全是这个问题。

影响面：**38 个函数中，目前只有 6 个做了属性缺失跳过。剩余 32 个需要审计。**

**（2）target_entities 粒度过粗**

典型如 `ACCESS-003` 匹配所有 `door`，但真实图纸中 99% 的 door 不是无障碍出入口。`DIM-002` 匹配所有 `room`，但 room 的 area 是坐标范围而非实际面积。

影响面：**函数匹配精度依赖语义分析器的实体分类精度。实体分类不准确 → 原子函数全量误报。**

**（3）规范逻辑缺乏上下文推理**

当前是单实体→单判定模式。但规范判定往往需要多实体关联推理：
- "疏散路径连通性"需要 room→door→corridor→exit 的路径搜索
- "防火分区面积"需要同一分区的 room 面积汇总
- "安全出口数量"需要按防火分区聚合

现有框架不支持跨实体推理。

### 2.2 语义分析器的能力瓶颈

**实体识别：**
- 12 张图纸 `accessible_door` 识别为 0（今天加了 TEXT 规则，但真实图纸中无"无障碍出入口"标签文本）
- `evacuation_lighting` 识别来自 INSERT 块名映射，但属性全空
- `room` 的 area 不可靠（bounding box 面积而非实际净面积）

**空间关系：**
- room↔door↔corridor 的 `connects_to` 关系未建立
- 导致 EVAC-001/004 的疏散分析全部失效

**属性推断：**
- door 的 width 仅 33% 有值（216/663）
- 无属性的 door/fire_zone/evacuation_lighting 无法判定

### 2.3 测试体系的问题

- **258 个单元测试全部基于合成图纸**，真实图纸覆盖率不足
- 真实图纸测试只有实体数量基线（允许 ±20% 浮动），没有违规判定基线
- 慢测试标记 `@pytest.mark.slow` 导致 CI 中默认跳过真实图纸测试

## 三、初心对照：正向解析 + 反向重构

### 3.1 当前定位

```
[需求/图纸] → [正向解析] → [违规报告]       ← 当前能力边界
                          → [知识图谱]        ← 未建立
                          → [推理引擎]        ← 未建立
                          → [反向重构]        ← 未启动
```

### 3.2 正向解析的深度目标

不满足于"检出违规"，而是"理解图纸"：

| 层级 | 当前 | 目标 |
|------|------|------|
| 图元识别 | YOLO + 图层规则，~80% 准确率 | 图元识别率 > 95%，属性推断完整 |
| 语义理解 | 38 个独立原子函数 | 规范知识图谱，支持跨实体推理 |
| 规范推理 | 单值比较（≥0.90m 等） | 上下文感知（楼层/分区/建筑类型联动） |
| 判定可信度 | PASS/FAIL 二元 | 置信度 + 推理路径 + 可解释 |

### 3.3 反向重构的技术挑战

从"能看懂"到"能生成"，中间需要跨越的能力层：

**（1）规范知识图谱**
- 将 GB50016/GB50763 等规范条文转化为结构化约束
- 约束之间的关系（优先级、冲突消解、层级依赖）

**（2）约束求解器**
- 给定需求参数（面积、层数、功能类型），求解合规的空间布局
- 输出：房间位置、门位置、走廊拓扑、疏散路径

**（3）图纸生成器**
- 约束解 → DXF/DWG 几何输出
- 支持：墙体绘制、门窗插入、尺寸标注、图块引用

### 3.4 两条路径的选择

| 路径 | 优点 | 风险 |
|------|------|------|
| A: 正向做深再做反向 | 根基扎实，逐步积累 | 反向启动慢，产品形态单一 |
| B: 反向从简易场景起步 | 快速验证生成能力，产品吸引力强 | 正向不足时反向生成的图纸可能不合规 |

**建议：以 A 为主，B 为辅。** 正向解析的精度达到"专业建筑师认可"（>90% 真实图纸检出率）之前，反向重构的价值有限。但可以启动简易场景的原型验证（如单一房间的合规布局生成）。
