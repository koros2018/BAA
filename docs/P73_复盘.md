# P73 多Sheet 审查复盘

> 日期：2026-07-27
> 问题：多Sheet 审查（/review-multi-sheet）连续返回 HTTP 500，4 轮修复才解决
> 最终：2006/2006 测试全绿，真实 DXF 多Sheet 审查通过

---

## 问题描述

用户使用多Sheet 审查功能（上传包含多个 Sheet 的 DXF/DWG 文件，每个 Sheet 独立审查后聚合报告）时，连续返回 HTTP 500。前端报错 `Unexpected token 'I', 'Internal S'...`，原因是服务端返回 HTML 错误页面，前端尝试 JSON 解析失败。

---

## 根因链（5 个 Bug，层层暴露）

### Bug #1 — 前端路径错误（404）
- **位置**：`src/frontend/baa-ext.js:774`
- **现象**：点击多Sheet 审查按钮后，请求 404
- **原因**：URL 为 `/api/v1/review-multi-sheet`，但 review 路由不挂载 `/api/v1` 前缀（`baa_api.py` 中 `router` 直接挂载，无 prefix）
- **修复**：去掉 `/api/v1` 前缀 → `/review-multi-sheet`
- **Commit**：`671d332`

### Bug #2 — 同步前端请求走异步队列（500 OOM）
- **位置**：`src/api/review/review_routes.py:1191` `/review-multi-sheet` 端点
- **现象**：请求到端点但返回 500，后端日志出现 OOM kill
- **原因**：端点使用 `wait_and_dequeue` 队列模式（max_concurrent=1），前端同步等待。大文件（5MB+）在排队时内存积压，300s 超时后触发 OOM → SIGKILL
- **设计错误**：多Sheet 审查是**同步用户请求**（浏览器等待结果），不应走异步队列。队列模式只适合后台批量任务
- **修复**：去掉队列，直接用 `run_in_executor` 线程池执行，前端同步等待结果返回
- **Commit**：`bf5eb18`

### Bug #3 — DrawingParser 内 to_dict 序列化（AttributeError）
- **位置**：`src/baa_engine/drawing_parser.py` `detect_sheets` mode
- **现象**：`AttributeError: 'dict' object has no attribute 'layer'`
- **原因**：`detect_sheets` 模式下存储 sheet 图元到 `sheets[]` 时调用了 `to_dict()`，把原始图元对象序列化成了 dict。后续 `analyze()` 方法期望的是带 `.layer` 属性的原始对象，不是 dict
- **修复**：`detect_sheets` mode 存储原始图元对象，不转 dict
- **Commit**：`40e62c1`

### Bug #4 — review_routes 二次 to_dict（AttributeError，同 #3 症状）
- **位置**：`src/api/review/review_routes.py:1498` 附近
- **现象**：修复 Bug #3 后仍然 `AttributeError: 'dict' object has no attribute 'layer'`
- **原因**：`review_routes.py` 在把 `sheet_entities` 传给 `analyze()` 之前，又调用了一次 `to_dict()`——两次序列化，修一层还有一层
- **修复**：`review_routes.py` 中也去掉 `to_dict()` 调用，直接传原始对象
- **Commit**：`7d959eb`

### Bug #5 — 闭包 import 遗漏（NameError）
- **位置**：`src/api/review/review_routes.py` `_do_sheet_review` 闭包内部
- **现象**：`NameError: name 'SpecRepository' is not defined`
- **原因**：`_do_sheet_review` 闭包中调用了 `SpecRepository()`，但 `SpecRepository` 的 import 写在 `_do_main_review` 闭包中（不同的作用域）。Python 闭包内的 import 不会自动继承外层同名 import
- **修复**：在 `_do_sheet_review` 闭包内部添加 `from src.baa_engine.spec_repository import SpecRepository`
- **Commit**：`3b128cf`

## 开发规范

### 📌 规则 1：不要对传给 analyze() 的图元调用 to_dict()
`analyze()` 的签名约定是接收**原始图元对象**（带 `.layer`, `.bbox` 等属性），不是 dict。`to_dict()` 是序列化给前端/缓存用的，永远不要在审查链路中调用。

**如何检测**：`AttributeError: 'dict' object has no attribute '...'` 且发生在 analyze() 调用链中 → 上游有 to_dict()。

### 📌 规则 2：闭包内的 import 必须独立
Python 的闭包作用域不共享外层 import。如果一个闭包（尤其是嵌套在异步函数内的闭包）需要某个模块，必须在**该闭包内**显式 import，不能依赖外层同名 import。

**反模式**：
```python
async def outer():
    from some.module import SomeClass  # 只在 outer 作用域
    def inner():
        SomeClass()  # NameError！
```

**正模式**：
```python
async def outer():
    def inner():
        from some.module import SomeClass  # 每个闭包自己 import
        SomeClass()
```

### 📌 规则 3：review 路由不加 /api/v1 前缀
review 路由直接挂载到 `app`，无 `/api/v1` prefix。所有前端调用 review 端点时 URL 以 `/review`、`/review/pdf`、`/review-multi-sheet` 开头，不要加 `/api/v1`。

**如何验证**：`curl http://127.0.0.1:8000/docs` 查看 OpenAPI 实际路由路径。

### 📌 规则 4：同步前端请求不要用异步队列
如果前端是**同步等待**（`await fetch()` 阻塞等待响应），后端不应该使用 `wait_and_dequeue` 队列模式。队列适合后台批量任务（如批量审查、定时审查），不适合单次用户交互。

**判断标准**：
- 前端页面等待按钮点击后的结果 → 同步，用 `run_in_executor`
- 前端提交后关闭弹窗、通过 webhook/polling 获取结果 → 异步，用队列

### 📌 规则 5：改一处检查同类模式
当一个 Bug 修复后仍出现相同症状，优先排查**代码中其他位置是否使用了相同模式**。

**本次案例**：Bug #3 修了 `drawing_parser.py` 的 `to_dict()`，Bug #4 发现 `review_routes.py` 也有同样的 `to_dict()`。如果修完 #3 先全局搜索 `to_dict` 再测试，可以一次修完。
