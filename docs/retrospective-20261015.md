## 二、五次方向级转折（本周期最重要的决策资产）

### 转折 1：YOLO/光栅路线证伪，矢量原生路线确立（P84/P101/P111）

**证伪证据链**：
- bbox 方案 mAP50：wall=0.03，door/window/stair≈0，类别倾斜（wall 91%）
- seg 方案 mask mAP 全 0 —— DXF LINE 零厚度渲染后 <1px，特征丢失
- P111 v2 伪标签全量 18 类训练 mAP50=0.001，彻底证伪

**替代方案**：P101 扫线法（左手定则平面面遍历）→ P103 PDF 轴对齐合并 → P104 面过滤 → P105 走廊/门洞 → P107 EVAC BFS 闭环。房间识别从"概率预测"变为"几何拓扑确定性"。

**专家结论**：CAD 图纸的语义（图层名、块名、XData、文字标注）**只存在于矢量数据中**，渲染为光栅后不可逆丢失。任何"先渲染再视觉识别"的路线在 CAD 领域都是根本性错误。YOLO 仅可保留为消防设备符号的专项补充手段，且须先完成矢量块名/图例查表基线。

### 转折 2：从"堆原子函数"到"修上游信息"（P74-P83 → 2026-08-17 复盘）

P57 曾 3 天从 58→390 爆发式扩展，但 P0 Benchmark 暴露：86% 审查结果是误报/漏检，32%（约 21,000）图元未分类，3 个 EXIST 函数占 FAIL 总量 97.7%。

**根因**：原子函数数量不是瓶颈，**上游实体属性抽取与拓扑聚合作用域缺失**才是。422 个函数已足够，继续叠加只会放大误报。

### 转折 3：工作流闭环补齐（P119）

审查→审核（确认/误报/待核实）→整改通知单→复查，从"演示 Demo"到"可交付产品"的关键一步。误报自动入 feedback_engine，为黄金标准扩库（P113）打通数据回路。

### 转折 4：前端技术债清零（P122-P126）

104 个 var / 72 个内联 onclick / 87 处 innerHTML+= 全部归零；Vite + TS strict + 组件化 + Vitest 27 用例 + Playwright 8 spec。前端可维护性从 2/10 提升到 ≥6/10。

### 转折 5：跨平台与依赖治理（2026-10-15，本日）

- Windows F1-F4 修复（CJK 字体 / shutil.which / shutil 作用域 / yolo_entities 预绑定）
- DWG 链路 4 处潜伏缺陷修复（ezdwg 未安装的警告长期掩盖了签名残留 self、裸 NameError、缺 import 等真实 bug）
- macOS CFF 字体容错（reportlab TTFont 不支持 CFF 轮廓 → TrueType 优先 + 逐候选 try/except）
- CI 数据门槛修复（缺图 SKIP 而非假阳性常红）

**元教训**：**未声明的可选依赖是缺陷温床** —— "优雅降级"的警告同时掩盖了降级路径上从未执行过的代码。核心依赖必须进 requirements.txt，由 CI 保证环境一致性。

## 三、根因模式归纳（可复用的缺陷分类学）

| 模式 | 典型案例 | 预防机制 |
|------|---------|---------|
| **光栅语义丢失** | YOLO mAP 断崖下跌 | 矢量原生约束（见 skill: cad-vector-native-parsing） |
| **降级路径从未执行** | F3 shutil.copy2 成功路径首次真正可用 | 可选依赖必须在 CI 中以"已安装"和"未安装"两种形态各跑一遍 |
| **序列化边界污染** | P73 to_dict 传入 analyze() 双重序列化 | 明确数据契约：审查链路只传原始图元对象，to_dict 仅用于前端/缓存出口 |
| **闭包 import 作用域** | P73 NameError: SpecRepository | 每个闭包独立 import，不依赖外层同名 import |
| **块展平丢语义** | 32% 图元无法分类 | 块引用提取必须保留块名/属性（S1 block_refs 已落地） |
| **几何判据过泛化** | 图例表被误识别为房间 | 多维度特征组合判定（单元格数量+尺寸+图层），且排除范围只到"贴边框图元"而非整个 bbox |
| **单平台验证偏差** | Windows 13 失败 / macOS CFF | 跨平台验证清单 + 三平台 CI job |
| **基线过计数** | 00582518a28e room=9 实为表格伪影 | 真实图纸基线变更必须附审查证据，禁止无依据调整 |

## 五、后续开发指南 Roadmap v3（2026-10-15 起）

> 排序原则：**商业验证 > 识别率验收 > 审查证据链 > 新产品能力**
> 禁令延续：禁止新增原子函数数量、禁止光栅主干路线、禁止无真实数据验证的 P 项

### 阶段 A（0-1 月）：验收闭环 + 商业破冰

| P 项 | 名称 | 交付 | 验收标准 |
|------|------|------|---------|
| **P135** | 天正 T3 识别率验收闭环 | 标注集（≥3 张 T3 图纸、4 类构件、每张 ≥50 实体）+ 基线测量 + 差距分析 | 墙 F1≥0.80、门窗 F1≥0.75，输出测量报告 |
| **S2** | 块语义分类（block_refs 下游） | 块名→构件类型映射表 + 图例查表基线 + 与 LAYER_RULES 联合判定 | 东莞通图纸未分类率再降 ≥50% |
| **P113** | 真实用户试用 | 3-5 个真实项目包（住宅/办公/数据中心/医院/工业各 1）+ 黄金标准 v2 | ≥3 份真实项目审计报告，黄金标准 +100 条 |
| **P118** | 商业模式验证 | 1 页产品定位 + 1 页定价表 + 5 个客户访谈 | 输出 MVP 边界文档 |

### 阶段 B（1-3 月）：证据链 + 产品化

| P 项 | 名称 | 交付 | 验收标准 |
|------|------|------|---------|
| **v2-P130** | 拓扑图 NetworkX 显式化 | topology_graph.py + /api/v1/topology 导出 | 节点数与真实房间偏差 ≤10% |
| **P132** | 闭环量化指标 | Hausdorff / 图编辑距离 / 语义匹配率 / 参数保真度 | 报告新增 4 项量化指标，偏差 ≤5% |
| **P116** | 报告产品化 | 封面/签字/项目信息/条款索引/结论页，PDF+HTML+Excel | 无乱码无空白章节 |
| **P112** | 协作前端收尾 | 认证入口 + 团队空间 + 评论审批 UI | 注册→协作全流程 E2E ≥8 用例 |

### 阶段 C（3-6 月）：部署 + 生态

| P 项 | 名称 | 交付 | 验收标准 |
|------|------|------|---------|
| **P115** | 云端部署流水线 | PostgreSQL 生产配置 + CI/CD + 可观测 | docker compose 一键生产就绪 |
| **P117** | 知识库开放 | 原子函数/规范 schema 版本化 + SDK 示例 | 一键导出知识库包，SDK 10 分钟跑通 |
| **P136** | 扫描件 OCR（解除阻塞后） | 真实扫描件样本集 + tesseract chi_sim 实测 | 矢量 100% / 扫描件 ≥85%（≥200DPI） |
| **P131** | IFC/STEP 输出 | IfcOpenShell IFC4 + CadQuery STEP | 5 张平面图 Hausdorff ≤2mm |

### 明确不做（6 个月内）

- GNN 拓扑推理、VLM 端到端审查、数字孪生 3D Tiles —— 商业价值未验证前不投入
- YOLOv11 迁移（v2-P129）—— 降级为"消防符号专项补充"研究项，不占用主线资源
- 新原子函数 —— 容量已满，新增需求走"阈值/规则调优"而非"加函数"

### 迭代纪律（沿用并强化）

1. 每个 P 项必须真实数据验证，验收指标同时覆盖误报率与漏报率
2. 每完成一组功能打 `-stable` 标签
3. 依赖变更必须同步 requirements.txt + CI 环境 + 跨平台清单
4. 基线变更必须附证据链（图纸 ID + 根因分析 + 前后对比）

## 七、一句话总结
