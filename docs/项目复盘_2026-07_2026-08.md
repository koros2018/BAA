## 二、核心成就

### 1. 扫线法房间检测（P101~P108）— 最重要的技术突破

从"依赖 YOLO 检测房间"到"纯几何扫线法 + YOLO 兜底"的范式转换：

- **P101**：左手定则平面面遍历，解决 O(n²) DFS 链式合并的性能问题
- **P103**：PDF 贝塞尔碎片化 → 轴对齐合并，房间 0→14
- **P105**：走廊独立识别（宽高比+短边分类）+ 门洞间隙检测
- **P107**：扫线法 doorway → EVAC BFS 拓扑闭环
- **P108**：门洞 gap_width_mm → DIM-006/DIM-009 自动触发

**价值**：扫线法比 YOLO 房间检测更快、更准、不依赖模型质量。真实图纸验证：4/4 建筑图 95-100% 覆盖率。

### 2. PDF 全链路（P99~P100）— 产品可用性突破

- PyMuPDF 矢量线条抽取 → ezdxf 标准化
- 比例尺自动恢复（pt→mm × scale）
- `DrawingParser.parse()` 直接消费 PDF，消除 PDF→DXF→分析的手动链路
- 一层平面图 94726 lines → door 152 / wall 49 / 6 个真实违规

**价值**：用户不需要预先转 DXF，PDF 直上直用。这是面向实际用户场景的关键跃迁。

### 3. 工程架构成熟度

- **大文件拆分**：`layer_rules.py` 1014→9 子模块，`fire_general.py` 2892→8 子模块，`review_routes.py` 1884→4 文件，`drawing_parser.py` 1556→448+dwg_convert+geometry
- **模块边界清晰**：每个功能领域独立文件/子模块
- **注释率**：核心文件 90%+ `# why` 注释（达标）
- **CI/CD**：GitHub Actions lint + test，真实图纸基线验证常态化

## 三、技术决策复盘

### 3.1 ✅ 正确的关键决策

| 决策 | 背景 | 结果 |
|------|------|------|
| **扫线法替代 DFS** | DFS O(n²) 大图纸超时 | 性能 100x+，房间覆盖率 95-100% |
| **保守策略（P109）** | 房间属性推断仅设 subtype 不 override | 避免 2 个 PDF 回归，扫线法计数不受影响 |
| **原子函数同步执行（P94）** | 线程池开销 227x | 4.9s AF 阶段（原 475s，97x） |
| **移除 YOLO 增强（P84-E）** | mAP≈0，误报率高 | 东莞通 0 违规误报 |
| **PDF 自动比例尺恢复（P99）** | 人工调参不可扩展 | 真实 PDF 首次即出结果 |

### 3.2 ⚠️ 值得复盘的曲折

| 曲折 | 根因 | 教训 |
|------|------|------|
| **P93 前端 5 轮修复** | 模板引擎与 JS 作用域冲突 + ID 命名错配 | 前端模块 ID 命名需提前约定 |
| **P84 分类器 4 次重写** | 阈值反复调整，缺少系统性分析框架 | 几何分类器应有统一的评估管线 |
| **P109 初版 2 个 PDF 回归** | room 类型 override 导致扫线法计数归零 | 修改全局语义前先做回归验证 |
| **P105 走廊短边阈值** | 4000mm 取整而非精确 3300mm | 阈值需要文档说明 why 而非 what |
| **P73 多 Sheet 5 轮修复** | 闭包/序列化/队列/路径 多个层级问题 | 复杂集成需要增量验证 |

### 3.3 ❌ 明确不可行的方向（P95）

**LAYER_RULES 扫尾（P95）— 结论：不可行**

7/9 真实图纸为 xref 空壳，东莞通全 layer=0。继续补图层规则的边际收益极低，扫线法 + 几何特征 是更优路径。
