## 二、工作流与用户体验审计

### 2.1 核心工作流：源头有缺陷

**当前BAA工作流：**
```
上传图纸 → 审查 → 看结果列表 → 结束
```

**行业标准工作流：**
```
上传图纸 → 自动解析 → AI审查 → 工程师逐条审核 → 标记(确认/误报/待核实) → 
生成整改通知单 → 设计院整改 → 复查 → 归档 → 生成合规报告
```

**BAA缺失的环节：**
- ❌ 工程师审核环节（逐条标记确认/误报/待核实）
- ❌ 整改通知单生成
- ❌ 复查与比对（对比前后版本差异）
- ❌ 归档与合规报告
- ❌ 多角色协作（设计师/审图工程师/项目经理/监理）

## 三、审查力审计

### 3.1 真实图纸审查能力

| 指标 | 数据 | 评价 |
|------|------|------|
| 原子函数总数 | 422 | 覆盖GB50016/50974/50116/50763 |
| 真实图纸违规 | 0 FAIL（P82降噪后） | 🟢 零误报是好，但可能过度降噪 |
| 批量审查135张 | OK 41 + SKIP 59 + SKIP_BIG 25 + TIMEOUT 4 + 未处理7 | 🟡 结构图59张跳过，大图25张跳过，实际可用率仅30% |
| 图形检测能力 | 扫线法房间++（P101-P108） | 🟢 进步明显，但仅限于建筑图 |
| 消防设备类 | 极弱（YOLO训练失败mAP50=0.001） | 🔴 18类仅10类有效，8类缺失 |
| 黄金标准 | 有（P97），但仅覆盖41条 | 🟡 规模太小，不足以代表真实场景 |

### 3.2 审查力根本问题

**问题1：YOLO模型训练失败，消防设备类识别归零**
- P111训练：mAP50=0.001，伪标签路径终止
- 根因：伪标签质量差，人工标注量不足
- 影响：消防设备（烟感、喷淋、灭火器、消防栓）8类完全缺失

**问题2：大图纸/结构图审查能力不足**
- 135张真实图纸中59张结构图SKIP（43.7%）
- 25张>20MB大图SKIP（18.5%）
- 实际可用率：41/135 = 30.4%
- 用户上传一张50MB的图纸直接跳过，体验极差

**问题3：** **`pass` 空吞异常**（后端严重问题）
- `drawing_parser.py` 6处 `pass` — 解析失败时静默吞异常
- `collab_routes.py` 7处 `pass` — 各种场景下静默处理
- `baa_api.py` 3处 `pass` — 占位/静默
- 后果：解析失败时用户看到的是"审查完成"但结果是空的，而不是"解析失败，请检查图纸格式"

**问题4：** **`except:` 裸异常捕获**（所有except都无特定类型）
- 全后端 `except:` 出现0次（都在用 `except Exception:` 或 `except:`）
- 但 `drawing_parser.py` 8处 `except Exception:` 全部无log/无traceback
- 后果：异常被吞，无法排查，用户看到空结果

**问题5：审查结果** **无置信度与可视化**
- 行业标准：违规在图纸上高亮标记，点击跳转
- BAA：纯文本列表，"违规：门宽0.8m，要求≥0.9m"
- 用户没法知道"哪个门"、"在图纸哪"

### 3.3 原子函数质量

| 维度 | 评价 |
|------|------|
| 覆盖广度 | 422个函数覆盖主要国标，但缺地标/企业自定义 |
| 判定精度 | 0%误报（P82降噪后），但 recall 未量化 |
| 阈值合理性 | 15%容差（P82），但可能过度宽松 |
| 链式依赖 | 已有（P32），但依赖图不完整 |
| 原子函数复用 | 高（参数化配置），但部分函数判定逻辑重复 |
| 错误信息 | 只有"PASS/FAIL"，无上下文（对比P29） |
