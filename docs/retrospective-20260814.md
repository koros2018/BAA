## 二、核心转折点：P101 扫线法

**P101-P105 是一条完整的架构链**，从"依赖 YOLO 识别房间"转向"用几何拓扑精确检测房间/走廊/门洞"。

```
P101 左手定则平面面遍历 → 房间检测（0→14 rooms）
  P102 基线重建（T3 空壳过滤）
  P103 PDF 轴对齐合并（PDF 碎片化解决）
  P104 面过滤增强（外框面/双线墙/去重）
  P105 走廊分类 + 门洞间隙检测
```

**为什么这是架构级转变**：

之前 BAA 的房间识别 = YOLO 预测 + LAYER_RULES 兜底，两者精度上限都受限于训练数据质量和图层规范性。扫线法基于**几何拓扑确定性**，对房间/走廊/门洞的检测不依赖模型预测，精度从"概率"变为"确定性"。

**代价**：P101 从 8d43167 → 181db3c 共 10 个 commits，平均每 commit 解决一个真实 bug。算法迭代路径：

1. pre-filter 消除 60% 噪声线
2. LINE 链闭合精度补偿
3. 左手定则 + T-junction 分割
4. 外框面剔除
5. LWPOLYLINE 直接提取
6. PDF 轴对齐合并
7. 面过滤三阶段
8. 走廊分类
9. 门洞间隙检测
10. 测试回归

**教训**：算法研发不要跳过中间验证。P101 如果从 commit 1 直接做到 commit 5，会无法定位每一步的根因。10 commits 不是"效率低"，是"每一步可追溯"。

## 三、关键问题分析

### 3.1 服务停服 6 天（08-08 ~ 08-13）

**现象**：日志零记录，服务离线。

**根因推断**：
- 08-07 19:59 旧实例正常关闭（SIGTERM），之后未重启
- 08-14 10:34 手动启动当前实例
- 期间无自动化重启/监控告警

**本质问题**：**BAA 缺少服务自愈能力**。gunicorn 进程没有 systemd supervisor 或 watchdog，进程退出后无人拉起。

**建议**：增加 systemd unit 或至少增加 restart=always 容器策略。

### 3.2 08-07 `_infer_attribute_name` TypeError

```
TypeError: _infer_attribute_name() takes 2 positional arguments but 3 were given
```

- 30 次异常集中在 08-07 19:43~19:58
- 旧代码：函数签名 `def _infer_attribute_name(dim, nearest)`
- 调用处：`_infer_attribute_name(dim, nearest)` 但外层通过 `self` 传递了 3 个参数
- 已在 0f3ea84 修复

**问题不在代码**：这是**接口变更未全量搜索调用点**的典型 bug。`git grep` 覆盖不足。

**建议**：接口变更时必须 `git grep -n 'function_name' src/` 验证所有调用点。

### 3.3 稳定标签密度过高

16 天打 13 个 stable tag。v2.5.28→v2.5.40 平均 1.2 天一个标签。

**问题**：标签是"发布点"，不是"进度标记"。每个 tag 应代表一个可部署的完整版本，而不是日常开发里程碑。

**建议**：
- stable tag 频率降至 3-5 天一个
- 日常 commit 不强制打 tag
- tag 只在实际需要部署/回退时打

### 3.4 测试 591 个函数但 CI 门禁缺失

CI（GitHub Actions）在 P39 已完成，但 baseline_verify 仅覆盖 6 张固定图纸 ±30%。

**缺口**：
- 无自动化部署后 smoke test
- 无真实图纸回归门禁（merge 前自动跑）
- 无性能基准（P94 的 97x 加速无持续监控）

## 五、扫线法 vs YOLO 决策树

```
检测到墙段？
├── 闭合多边形 → 扫线法 → room（确定性）
├── 平行线 gap [700,2500]mm → 扫线法 → doorway（确定性）
├── 面积/宽高比 → 扫线法 → room/corridor 分类（确定性）
└── 其他（消防设备/电气符号/文字标注）→ YOLO + LAYER_RULES（概率性）
```

**核心原则**：能用几何拓扑解决的不用模型。模型只处理几何无法处理的（消防设备、图例符号）。

## 七、经验提炼

### 这次做对了什么

1. **扫线法是正确决策**：不依赖模型的确定性检测，精度上限由几何拓扑决定，不受训练数据分布影响
2. **真实图纸基线常态化**：P81 的 CI baseline_verify 让每次修改都有 6 张真实图纸验证
3. **原子函数全量单测**：1563/1563 为大规模重构提供了安全网
4. **逐步迭代**：P101-P105 分步推进，每步可独立验证

### 这次没做好什么

1. **服务自愈缺失**：6 天离线无人发现
2. **接口变更未全量搜索**：08-07 TypeError
3. **标签频率失控**：13 个 stable tag/16 天
4. **P107 未跟紧**：P105 已产出 corridor+doorway，但未立即接入 EVAC，中间有断档
5. **文档更新滞后**：ROADMAP 直到 08-14 才更新到 P105

### 核心教训

**开发节奏问题不是速度问题，是衔接问题**。P101→P105 五步链完整但 P105→P107 有 gap。扫线法产出了 corridor/doorway 却没有立刻接到 EVAC，说明"能力产出"和"能力消费"之间缺少自动串联机制。
