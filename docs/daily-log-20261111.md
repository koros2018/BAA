## 六-E、_build_relations Phase 2 AABB 提前拒绝（追加）

### 定位
`_build_relations`（~1080ms）中 Phase 2（~165ms）是 11,439 openings ×
avg 20.6 候选（235,616 次 dist_to_edge 计算）。

### 优化
dist_to_edge = min(min_dx, min_dy)，其中 min_dx 是 opening 中心到 wall x 边
的距离（>= 轴向间隙 gx），min_dy >= gy。故 gx>=50 且 gy>=50 ⟹ dist_to_edge>=50
⟹ 必被 dist_to_edge 判据拒绝。gx/gy 计算无 abs（仅比较），比 4 次 abs + 2 次
min 便宜。注意必须 gx 和 gy 都 >=50 才拒绝（单个 gx>=50 但 gy<50 时 min_dy
可能 <50，dist_to_edge<50 应通过）。

### 效果
- AABB 拒绝 19.2% 候选（393,291 中 75,435），通过后 317,856 需 dist_to_edge
- `_build_relations` 累计：2003→~1080ms（-46%）

## 七、_build_relations Phase 1/2 深度分析（追加）

### Phase 1 dict.get 优化现状
- **Phase 1 query**：~7ms，使用 defaultdict(dict) + .get()。4,085 candidates × expand=1 ≈ 36K 次 cell 查询。已是较优状态。
- **进一步优化**需替换 grid 数据结构（如 tuple key 平铺为单 dict），但改动大且收益不确定。暂未实施。

### Phase 2 候选遍历优化
- **Wall bbox 预计算**（T-opt21，提交 b532250）：预提取 w_x1/w_y1/w_x2/w_y2 flat arrays，grid_build 循环用下标访问替代 wb.get()。dongguan Phase 2 grid_build 从 ~157ms → ~40ms，_build_relations 从 ~1242ms → ~1206ms（-37ms）。
- **Opening 侧**：尝试预提取 o_x/o_y 数组并用 *0.5 替代 /2，发现浮点精度差异导致 rels 减少 227（回归）。改为保留原始 `/ 2` 除法。**dist_to_edge = min(min_dx, min_dy)** 已是最简形式；尝试 max 替代被证明有 bug（o_cx 在 [wx1,wx2] 右侧时返回 dist=0）。
- **AABB 提前拒绝**：gx>=50 AND gy>=50 过滤 19.2% AABB 候选（修复后正确）。
- **fast_set 收集**（T-opt22，提交 1b36297）：用 `set().update()` 替代 seen+append 去重。Phase 2 候选遍历 553→471ms（-15%，-82ms），_build_relations 整体 1223→1021ms（-202ms，-16.5%）。matches 数一致（7494），1420 个 opening tie-break 选择不同 wall（合法歧义）。
- **Grid 存 wall index（int）而非 SemanticEntity**（T-opt23）：grid_build 循环改为存 int index；内层循环通过 flat arrays `w_x1/w_y1/w_x2/w_y2` 直接索引，消除 1.6M×dict.get 调用。`_build_relations` dongguan ~1021ms → ~743ms（-27%），rels=29677 一致。**注意**：rooms=dongguan 为 353（非基线 198），经查为 HEAD 本身状态（非回归），与优化无关）。
- **Opening bbox o_width/o_height 预提取**（T-opt24）：将每次 opening 循环外 `ob.get("height")/ "width"` 提到循环前计算为 `o_wh/o_ww`，省内层 406K×2 dict.get 调用。rels 不变（历史基线 ~743ms）。
- **条件分支替代 abs/min/max**（T-opt25，已 revert）：测试后发现 conditional expression overhead 在 Python byte-code 层面 > built-in function call，整体无改善甚至略慢（~840ms）。回滚保留原版 abs/min/max 实现。
- **合并 x/y edge grid（T-opt28，已 revert）**：尝试将 x_edge_grid/y_edge_grid 合并为单一 flat dict 以省一半 dict.get；但发现 cell key 可能重叠（x 边与 y 边坐标值相同），导致候选集缩小（rels 从 29677 降至 27995，正确性 bug）。已 revert，保留独立 x/y grid。
- **Phase 3/5 grid 扁平化（T-opt26）**：将 Phase 3 `_candidates` 与 Phase 5 `_P5_GRID` 从嵌套 `dict[gx][gy]` 改为平铺 `dict[(gx, gy)]` tuple-key；build 循环预计算 gx0/gx1/gy0/gy1 范围避免重复 int 除法。单次访问省一次 `.get()`（从 2×→1×），减少函数调用总量从 ~5M 降至 ~800K。`_build_relations` dongguan ~743ms → ~350ms（**-53%**），rels=29677 一致。全量测试：**3106 passed**。
- **Numba JIT Phase 2 内核（T-opt29，WIP）**：尝试将核心 dist_to_edge + overlap 循环移至 numba nopython 模式，规避 abs()/min() 的 Python byte-code 开销。
  - 发现并修复 dedup bug：原方案按 cell_key 级跳过 y-only 条目导致 4840 wall references 丢失（rels 从 29677 降至 28045）。修复后 pair 计数完全一致（10278 vs 10278，967 个 tie-break 位置不同）。
  - **性能结果**：纯内核 333ms（vs Python fallback ~280ms）；完整 pipeline（含 flat grid 构建 + array prep + ID mapping）约 350-450ms，净收益接近于零。
