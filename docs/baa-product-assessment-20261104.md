## 5. 缺口登记（按优先级）

### P0 · 立即

1. **规则可达性突破 50%**
   - 当前 40.8%，距 50% 门槛差约 40 条规则可命中
   - 主要增量：解析层补齐 `staircase / corridor / window` 类型识别（当前真实图纸产出率为 0）
   - 目标：staircase 识别率 ≥ 80%，corridor 识别率 ≥ 60%

2. **空间索引（_build_relations）**
   - 当前：5334 图元单次 _build_relations 约 23 s，是万级图元的主要耗时来源
   - 方案：网格/R-tree 替代全量 O(n²) 距离计算，目标 ≤ 2 s
   - 影响：建筑类图纸审查响应时间从 28.7 s → ≤ 5 s（上线门槛）

### P1 · 近期

3. **三套规则执行循环收敛**
   - baa_api.py、_shared.py、review_routes.py 各有一套 near-duplicate 实现
   - 目标：所有审查入口共用同一执行循环（单一 rule_runner）

4. **coverage 字段测试补充**
   - P0-2 已在 review_routes.py 中实现 coverage 字段，但回归测试覆盖尚不充分
   - 目标：insufficient_evidence 语义的回归测试覆盖 ≥ 3 个场景

### P2 · 中期

5. **天正 T3 原生解析闭环**
   - 当前 T3 图纸依赖 ODA 转 DXF 兜底
   - 目标：T3 图纸不依赖外部工具，native parse 路径可用

6. **样本库清洗**
   - data/files/ 中 53% 为 16B 测试桩
   - 目标：清理至 0 个测试桩；基线脚本增加"内容有效性"门槛

## 6. 结论

**从"可用原型"升级为"准生产级"。**

两轮迭代共解决三项硬风险：密钥泄露（已闭环）、假满分（已闭环）、数据污染（已闭环）。全量 32 张图纸扫描 FAIL 归零，规则可达性 13% → 40.8%，安全评分 1.7 → 3.0。

当前产品力的真正瓶颈已从"**会不会出错**"转移到"**能不能算得有意义**"——40.8% 可达性意味着还有约 60% 的规则在当前真实图纸上无法落地。下一阶段的核心工作：

1. **P0**：staircase/corridor/window 类型识别（目标可达性 ≥ 50%）
2. **P0**：_build_relations 网格索引（目标 ≤ 5 s 审查响应）
3. **P1**：三套规则执行循环统一为单一 rule_runner

暂缓新增规则和视觉模型投入，直到可达性突破 50% 且审查性能达到上线门槛。
